# Техническое задание: Telegram-бот для коллабораций

## 1. Общая идея

Telegram-бот предназначен для поиска и организации коллабораций между:

- блогерами;
- Telegram-каналами;
- заведениями;
- брендами;
- фотографами;
- организаторами мероприятий;
- другими участниками, которым может быть интересно совместное продвижение или сотрудничество.

Основная механика:

1. Один пользователь создаёт предложение о коллаборации.
2. Указывает, что он готов предложить и кого или что хочет получить со стороны партнёра.
3. Другой пользователь находит подходящую коллаборацию.
4. Откликается на неё.
5. Автор коллаборации рассматривает отклик.
6. При взаимном интересе стороны получают возможность связаться друг с другом.
7. После проведения сотрудничества коллаборация завершается.

---

## 2. Формат первой версии

Первая версия продукта реализуется полностью внутри Telegram-бота.

Telegram Mini App в MVP не используется.

Взаимодействие происходит через:

- сообщения Telegram-бота;
- inline-кнопки;
- пошаговые сценарии;
- карточки коллабораций;
- уведомления.

При этом бизнес-логика не должна быть жёстко зашита непосредственно в обработчики Telegram.

Архитектурно бот должен работать через отдельный backend и базу данных.

```text
Collaboration Bot
        ↓
     Backend
        ↓
   PostgreSQL
```

Существующий бот для проведения розыгрышей остаётся отдельным Telegram-ботом, но может использовать тот же backend/API и связываться с коллаборациями на уровне данных.

```text
Collaboration Bot ───┐
                     ├── Backend / API ─── PostgreSQL
Giveaway Bot ────────┘
```

Это также должно позволить в будущем, при необходимости, подключить Telegram Mini App без переписывания основной логики продукта.

```text
Collaboration Bot ───┐
                     ├── Backend
Telegram MiniApp ────┘
```

## 3. Главная сущность

Все варианты сотрудничества являются одной общей сущностью:

`Collaboration`

Не нужно создавать отдельную сущность для:

- коллаборации блогера с заведением;
- коллаборации между блогерами;
- совместного розыгрыша.

Различия определяются типом коллаборации и её дополнительными данными.

### Базовые данные Collaboration

Коллаборация содержит:

- автора;
- название;
- описание;
- город;
- тип;
- кого ищет автор;
- что предлагает автор;
- что хочет получить;
- дату или дедлайн;
- статус;
- отклики.

---

## 4. Типы коллабораций

В первой логике предусмотрены разные сценарии одной сущности `Collaboration`.

Примеры типов:

- рекламная интеграция;
- бартер;
- совместный розыгрыш;
- совместный контент;
- взаимный PR;
- мероприятие;
- другое.

Тип коллаборации определяет, какие дополнительные вопросы бот задаёт пользователю.

---

## 5. Участники и тип коллаборации

Формат «блогер × блогер» не является отдельным типом коллаборации.

У коллаборации отдельно определяется:

- тип сотрудничества;
- кто её создал;
- кого ищет создатель.

Например:

```text
Тип: Совместный розыгрыш
Создатель: Блогер
Кого ищет: Блогера
```

Другой вариант:

```text
Тип: Совместный розыгрыш
Создатель: Блогер
Кого ищет: Бренд или заведение
```

Один розыгрыш потенциально может включать несколько участников:

```text
Блогер × Блогер × SPA × Цветочный магазин
```

---

## 6. Специализированные данные

Специфичные данные конкретного типа коллаборации не должны храниться как обязательные поля для всех коллабораций.

Например:

```text
Collaboration
  └── type = giveaway
      └── GiveawayDetails
```

или:

```text
Collaboration
  └── type = promotion
      └── PromotionDetails
```

---

## 7. Совместный розыгрыш

Совместный розыгрыш является одним из типов `Collaboration`.

При выборе типа «Совместный розыгрыш» бот задаёт дополнительные вопросы.

### Данные розыгрыша

Пример дополнительных данных:

- количество партнёров;
- сколько партнёров ещё требуется;
- приз инициатора;
- что предоставляет инициатор;
- требования к призу партнёра;
- что должен предоставить партнёр;
- условия участия;
- дата старта;
- дата подведения итогов.

### Пример

```text
🎁 Ищу партнёра для совместного розыгрыша

Город: Екатеринбург
Тематика канала: lifestyle / интересные места
Аудитория: 1 500 подписчиков

Мой приз:
Сертификат в SPA на 5 000 ₽

От партнёра:
Нужен второй приз примерно сопоставимой ценности

Условия:
— подписка на мой канал
— подписка на канал партнёра
— реакция на пост

Дата:
10–17 сентября
```

Кнопка:

`Предложить участие`

---

## 8. Розыгрыш с несколькими партнёрами

Создатель может искать не только одного партнёра, но и несколько.

Пример:

```text
Розыгрыш «День для себя»

Уже участвуют:
— блогер;
— SPA.

Ищем:
— ресторан;
— цветочный магазин.
```

В карточке можно показывать количество занятых мест:

```text
2 из 4 мест занято
```

Для розыгрыша должны поддерживаться два сценария:

1. поиск одного партнёра;
2. сбор нескольких партнёров.

---

## 9. Вклад каждого участника розыгрыша

Для каждого участника можно фиксировать:

- какой приз он предоставляет;
- какие публикации делает;
- какой вклад вносит в коллаборацию.

Пример:

| Участник | Приз | Что делает |
|---|---|---|
| Блогер А | SPA 5 000 ₽ | пост + Stories |
| Блогер Б | ужин 4 000 ₽ | пост + Stories |
| Заведение | сертификат | предоставляет приз |

## 10. Профиль пользователя

Профиль не должен заполняться большой обязательной анкетой сразу после `/start`.

Пользователь может сначала открыть бота и увидеть основные действия. Создание минимального профиля запускается тогда, когда профиль действительно нужен, например при попытке:

- создать коллаборацию;
- откликнуться на коллаборацию.

Бот сообщает:

```text
Для начала создадим короткий профиль.
```

### Telegram-пользователь и профиль

Telegram-аккаунт пользователя и профиль участника сервиса являются разными сущностями.

Один Telegram-пользователь потенциально может представлять несколько проектов.

```text
TelegramUser
      │
      ├── Profile №1 — блогер
      ├── Profile №2 — Telegram-канал
      └── Profile №3 — бренд / заведение
```

Даже если в первой версии интерфейс позволяет использовать только один профиль, структура данных должна допускать несколько профилей у одного Telegram-пользователя.

### Первый шаг создания профиля

Бот спрашивает:

```text
От чьего имени вы участвуете?
```

Варианты:

```text
Блогер
Telegram-канал
Заведение / бренд
Специалист
Другое
```

### Профиль Telegram-канала

Если пользователь выбирает Telegram-канал, по возможности нужно использовать нативный выбор канала в Telegram вместо ручного ввода ссылки.

Сценарий:

```text
Какой канал вы представляете?

[Выбрать мой канал]
```

После выбора бот получает доступные данные канала и использует их для заполнения профиля, например:

- Telegram ID канала;
- название;
- username;
- фотографию.

Далее бот спрашивает только данные, которых нет в Telegram.

Например:

```text
Выберите тематики:
Lifestyle
Food
Travel
Beauty
Город
```

Также могут запрашиваться:

- город;
- короткое описание;
- другие площадки;
- средние охваты;
- размер аудитории;
- примеры работ.

Если данные Telegram можно получить автоматически, пользователь не должен вводить их вручную.

### Для блогера

Профиль может содержать:

- имя;
- тип пользователя;
- город;
- тематики;
- ссылки на площадки;
- Telegram;
- Instagram;
- VK;
- TikTok;
- YouTube;
- размер аудитории;
- средние охваты;
- описание;
- примеры работ.

Пример:

```text
Татьяна Стрельчук
Блогер
Екатеринбург

Тематика:
Lifestyle / рестораны / путешествия

Telegram — 900
Instagram — ...
Средний охват Reels — ...

Примеры работ → ссылка
```

### Для заведения или бренда

Можно хранить:

- название;
- категорию;
- город;
- ссылку;
- короткое описание;
- контактное лицо.

### Постепенное заполнение профиля

Профиль заполняется постепенно по мере использования сервиса.

На старте достаточно минимального набора данных, необходимого для создания коллаборации или отклика.

Например:

```text
Telegram-канал
Екатеринбург
Lifestyle / Food
```

Если позже пользователю требуется функция, для которой не хватает данных, бот запрашивает их в этот момент и сохраняет в профиль.

Пример:

```text
Укажите средний охват публикации.
```

После ввода значение сохраняется и повторно не запрашивается.

То же относится к:

- ссылке на Instagram;
- средним охватам;
- размеру аудитории;
- дополнительным площадкам;
- другим данным профиля.

Принцип:

```text
Не большая анкета при входе
        ↓
Минимальный профиль
        ↓
Постепенное дополнение по мере использования
```

## 12. Создание коллаборации

Создание происходит пошагово через сообщения и кнопки Telegram.

### Шаг 1. Пользователь нажимает

`➕ Создать коллаборацию`

### Шаг 2. Бот спрашивает

```text
Что хотите организовать?
```

Варианты:

```text
Рекламная интеграция
Бартер
Совместный розыгрыш
Совместный контент
Взаимный PR
Мероприятие
Другое
```

### Шаг 3. Бот спрашивает, кого ищет пользователь

Например:

```text
Блогера
Бренд
Заведение
Фотографа
Неважно
```

### Шаг 4. Бот последовательно собирает данные

Например:

- что предлагает автор;
- что хочет получить;
- количество партнёров;
- город;
- сроки;
- дополнительные требования.

Список вопросов зависит от выбранного типа коллаборации.

### Шаг 5. Предпросмотр

Перед публикацией бот показывает готовую карточку.

Пример:

```text
🎁 Совместный розыгрыш

Екатеринбург
Ищу: блогера
Нужно партнёров: 1

Я предоставляю:
сертификат на 5 000 ₽

От партнёра:
приз сопоставимой стоимости

Даты:
10–17 сентября
```

Кнопки:

```text
✅ Опубликовать
✏️ Изменить
```

## 14. Просмотр карточек

В первой версии карточки можно показывать последовательно внутри Telegram.

Пример:

```text
Коллаборация №1

[данные коллаборации]
```

Кнопки:

```text
Откликнуться
Следующая →
```

Такой формат считается подходящим для MVP при небольшом количестве предложений.

Если количество предложений значительно вырастет и поиск через последовательные кнопки станет неудобным, в будущем может быть добавлен Telegram Mini App.

## 15. Отклик

Контакты автора коллаборации не обязательно показывать сразу.

Пользователь нажимает:

`Откликнуться`

После этого бот может попросить короткое сообщение:

```text
Почему вам интересна эта коллаборация?
```

К отклику автоматически прикладывается профиль пользователя.

Пример сообщения:

```text
Я веду блог про Екатеринбург, регулярно делаю обзоры ресторанов.
Средний охват Reels — 15–25 тыс.
Готова предложить Reels + Telegram.
```

Предлагаю сертификат ресторана на 4 000 ₽.
Канал — 2 300 подписчиков.
Тематика — food / lifestyle.

Можно указывать:

- приз;
- стоимость приза;
- публикации;
- другие условия участия.

## 18. Взаимный интерес

Если автор выбирает положительный вариант:

```text
Интересно
```

бот сообщает обеим сторонам:

```text
🎉 У вас взаимный интерес.
Теперь вы можете связаться напрямую.
```

После этого бот может показать контакты обоим участникам.

До принятия отклика прямые контакты могут оставаться скрытыми.

## 19. Коллаборация от блогера

Инициатором предложения может быть не только бренд или заведение.

Блогер также может создать коллаборацию.

Пример:

```text
Ищу коллаборацию в Нижнем Новгороде 12–15 сентября.

Снимаю городской lifestyle-контент.

Рассматриваю:
— отели;
— рестораны;
— SPA;
— необычные локации.

Могу предложить:
— Telegram;
— Reels;
— Stories.
```

На такое предложение могут откликаться заведения и бренды.

То есть сервис работает в обе стороны.

## 20. Telegram-канал как витрина

Обсуждалась схема:

- бот является основной системой;
- Telegram-канал используется как витрина новых коллабораций.

После создания и модерации предложение может автоматически публиковаться в канале.

Пример:

```text
🍝 РЕСТОРАН × БЛОГЕРЫ
Екатеринбург

Ищут 5 lifestyle / food-блогеров

Бартер:
ужин на двоих

Необходимо:
Reels + Stories

#Екатеринбург #Рестораны #Бартер
```

Кнопка:

```text
Посмотреть коллаборацию
```

Она ведёт в Telegram-бот на конкретную коллаборацию.

Канал используется для привлечения трафика, а бот — для управления коллаборациями и откликами.

## 21. Интеграция с существующим Giveaway Bot

Существующий Telegram-бот для проведения розыгрышей остаётся отдельным ботом.

Он не должен объединяться с Collaboration Bot в один большой Telegram-бот.

Разделение ответственности:

```text
Collaboration Bot
— найти партнёра;
— создать коллаборацию;
— собрать отклики;
— выбрать участников.

Giveaway Bot
— настроить;
— запустить;
— провести;
— завершить сам розыгрыш.
```

При этом боты должны быть связаны через общий backend/API и данные.

### Переход из коллаборации в розыгрыш

После того как для коллаборации типа «Совместный розыгрыш» найден и принят партнёр, Collaboration Bot показывает:

```text
🎉 Партнёр найден.

[🎁 Создать розыгрыш]
```

Кнопка открывает Giveaway Bot через Telegram deep link с параметром `start`.

Пример логики:

```text
Collaboration #841
        ↓
Создать розыгрыш
        ↓
Deep link в Giveaway Bot
        ↓
Giveaway Bot получает контекст коллаборации
```

Переход не должен вести пользователя просто на пустую главную страницу Giveaway Bot.

Giveaway Bot должен понимать, из какой коллаборации пришёл пользователь.

### Автоматическая передача известных данных

Если данные уже были собраны в Collaboration Bot, их не нужно спрашивать повторно.

Например, Giveaway Bot может получить:

- участников;
- Telegram-каналы участников;
- приз инициатора;
- приз партнёра;
- вклад каждого участника;
- условия, уже указанные при создании коллаборации;
- даты, если они были заполнены.

Пример:

```text
🎁 Создать розыгрыш по коллаборации

Участники:
✓ Канал А
✓ Канал Б

Призы:
✓ SPA — 5 000 ₽
✓ Ужин — 4 000 ₽

[Продолжить настройку]
```

После этого пользователь настраивает только параметры, необходимые непосредственно для проведения розыгрыша.

### Связь сущностей

На этапе поиска партнёров розыгрыш существует как тип `Collaboration`.

После того как партнёры найдены и пользователь запускает проведение розыгрыша, создаётся отдельная сущность `Giveaway`.

```text
Collaboration
id: 841
type: giveaway
status: matched

        ↓ creates

Giveaway
id: 322
source_collaboration_id: 841
```

Таким образом:

- `Collaboration` отвечает за поиск и согласование партнёров;
- `Giveaway` отвечает за проведение самого розыгрыша.

### Синхронизация завершения

После завершения розыгрыша Giveaway Bot сообщает backend о результате.

Связанная коллаборация также может быть переведена в завершённое состояние.

```text
Giveaway completed
        ↓
Collaboration #841
        ↓
status = completed
```

После этого Collaboration Bot может перейти к стандартному сценарию завершения сотрудничества и оценки партнёров.

## 22. Завершение коллаборации

После сотрудничества бот может спросить:

```text
Коллаборация состоялась?
```

Варианты:

```text
Да
Нет
```

Если сотрудничество состоялось, можно предложить оценить партнёра.

Пример:

```text
Как прошло сотрудничество?

⭐ 1–5
Комментарий
```

В профиле в дальнейшем может отображаться:

```text
12 завершённых коллабораций
4,9 ★
```

## 24. Подбор подходящих коллабораций

Вместо обязательного просмотра большого каталога сервис потенциально может работать как система мэтчинга.

Бот знает профиль пользователя и может присылать ограниченное количество подходящих предложений.

Например:

```text
Для вас найдено 3 подходящие коллаборации.
```

Это позволяет дольше сохранять интерфейс классического Telegram-бота без необходимости сразу разрабатывать Mini App.

## 25. Telegram Mini App

В первую версию Telegram Mini App не входит.

Решение о его разработке принимается только при появлении реальной необходимости.

Признаки, при которых Mini App может стать полезен:

- большое количество коллабораций;
- сложные фильтры;
- десятки результатов поиска;
- необходимость быстро менять параметры фильтрации;
- сравнение предложений;
- большое количество избранных;
- сложное редактирование профиля;
- несколько активных коллабораций;
- большое количество откликов;
- статистика;
- фотографии и портфолио.

Принцип:

> Начать с Telegram-бота и заставить Mini App доказать свою необходимость.

## 28. Основной принцип MVP

Первая версия должна проверить основной продуктовый цикл:

```text
Создают ли пользователи коллаборации
        ↓
Находят ли их другие пользователи
        ↓
Откликаются ли они
        ↓
Принимают ли авторы отклики
        ↓
Происходят ли реальные коллаборации
```

Приоритет первой версии — проверить эту механику, а не создавать сложный интерфейс.
